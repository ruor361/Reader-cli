# 阅读体验优化：三个讨论方向

日期：2026-10-13。范围：基于当前工作区的终端阅读器做头脑风暴，仅记录方案，未实现功能。

当前已经支持行宽调整、沉浸模式、搜索高亮、搜索结果列表和书签列表。本次聚焦阅读过程中容易中断的三个时刻。下述痛点是待验证的产品假设，并非用户研究结论；这里记录可供讨论的依据、取舍和验证方法。

## 1. 翻页留一点上下文，减少重新找句子的成本

**现状依据：** 当前按屏幕高度切分文本，前后屏没有重叠；长段落可能在句子中间跨屏。见 [pagination.rs](../../src/pagination.rs) 的 `paginate_with_content_dimensions`。

**建议：** 提供可关闭的“翻页衔接”：下一屏顶部保留上一屏最后一行，用轻量标记区分已读内容，新内容从下一行开始。首版只试一行重叠，不增加动画。

**使用情景：** 上一屏末尾读到“他推开门，看到……”，翻页后仍能看到这句开头，视线可以顺着读下去。

**取舍：** 重叠会少显示一行新内容，小窗口尤其明显；跨章节不必重复上一章结尾。重复展示不能导致进度倒退，也不能重复计算阅读量。位置仍应绑定原文，而不是屏幕行号。

**怎么验证：** 用同一段跨屏长文本对比开关前后，观察是否减少回翻，以及重复一行是否反而干扰。中文小说和英文长段落都试一次。

## 2. 查完就回来：给跳转加一个临时返回点

**现状依据：** 目前可以通过目录、搜索和书签跳转，但阅读状态与动作列表中没有跳转历史或返回动作。见 [reader_state.rs](../../src/reader_state.rs) 的 `ReaderState`、`ReaderAction` 和 `jump_to_position`。

**建议：** 在离开正文去查目录、搜索结果或书签时，自动保留出发位置；提供“一键返回查阅前”的操作。首版只保留一个会话内返回点，连续浏览搜索结果时不覆盖它。

**使用情景：** 读到第八章，搜索一个人物第一次出场的段落，看完直接回到第八章，不需要提前打书签或记百分比。

**取舍：** 临时查阅和转去别处继续读需要明确区分。建议返回点一直保留到返回、明确结束本次查阅或退出；不要因为普通翻页就悄悄丢弃。首版沿用当前位置保存规则，并说明临时返回点不会跨重启保留。具体快捷键留待检查现有绑定后确定。

**怎么验证：** 从正文出发，连续查看三个搜索结果，再执行返回；应回到出发处。期间调整窗口大小、行宽或开关沉浸模式，也应回到同一原文位置。

## 3. 续读时给一个轻提示，帮助找回上下文

**现状依据：** 当前启动时恢复已保存的原文位置，并定位到对应屏幕；初始化时没有续读提示。正常状态栏已有章节信息。见 [reader_state.rs](../../src/reader_state.rs) 的 `ReaderState::new` 和 [reader_view.rs](../../src/reader_view.rs) 的 `status_line`。

**建议：** 重新打开有进度的书时，在已保存位置对应的行旁短暂标记“上次阅读位置”，第一次翻页后消失；允许按需查看该位置前的一小段原文，关闭后继续阅读。直接使用原文上下文即可。

**使用情景：** 隔天回来，或窗口尺寸已经变了，读者能快速知道从哪里接着读；忘记上下文时再主动回看。

**取舍：** 当前保存位置通常代表屏幕起点，不能声称知道读者最后看到了哪个字。提示应轻量、可关闭，不强制弹窗；隐蔽模式和隐藏模式不展示正文摘录。查看上下文不应改变保存进度。

**怎么验证：** 隔一段时间重新打开同一段内容，比较找到续读起点所需的操作与时间；再用不同窗口宽度复查标记位置，并观察提示是否打扰连续阅读。

## 建议先讨论哪一个

优先考虑 **第 2 点“一键返回”**：它能补齐现有搜索、目录和书签跳转后的操作闭环，使用场景明确。其次是第 1 点，它影响每次翻页，但需要确认用户是否接受重复内容。第 3 点适合经常中断、分多次阅读的使用习惯。

本轮只新增这份讨论文档。现状已对照源码；体验收益仍需实际试读验证。

## 第二轮：文字在终端里，能不能长成另一种样子？

用户补充：上面的操作体验建议保留；本轮关注人眼面对文字时的排版、形式与阅读感受。仍只讨论三个方向，不写代码。

从当前源码看，普通正文主要采用统一样式，按可用宽度折行、按高度分屏。以下尝试改变文字的空间组织方式。它们是设计假设，不代表已经证实能减轻疲劳或提高阅读速度。示意文字为本次虚构。

### 方向一：有留白、有疏密的“纸页”

**想象的画面：** 终端很大，正文却只占中间一块安静的区域。左右宽边距，上方有一点空白；章名独占位置，与正文拉开距离。正文段内紧凑，段间略松。遇到章节结束，允许下面留下大片空白。

这比现有的调节行宽更进一步：设计一整页的比例、密度和空白，而不只是把文字栏变窄。页脚可以只有一个很淡的位置标记，视觉中心始终留给正文。

```text
                 第七章
                 雨停之后


      雨停了。屋檐还在滴水，远处有人
      推开窗，街道慢慢有了声音。

      他把信折好，放回桌角。



                         ·  七  ·
```

**希望带来的感觉：** 字有地方停，眼睛有地方歇。用留白表达章节、段落和停顿，不需要给正文加很多颜色。

**值得大胆试的细节：** 宁可一页少放几行，也尽量不让新段落只露出孤零零的一行；章末留白就是版面的一部分，不急着塞入下一章。

**边界与验证：** 留白过多也可能让人觉得松散、翻页频繁。先比较同一段文字的紧凑版和疏朗版，分别看第一眼的舒服程度与连续读十分钟后的感受。示意中的垂直空白以整行表达；字体、字号和更细的行距另行考虑终端支持情况。

### 方向二：让文字按语气排成“语流”

**想象的画面：** 一行结束的位置尽量贴近一句话里的自然停顿。短句保持短，长句在合适的分句处换行；对话保留独立段落。右边缘参差一些，整页像有人在缓缓讲述。

```text
      雨停了。
      屋檐还在滴水，
      远处有人推开窗，街道慢慢有了声音。

      “你还走吗？”

      他把信折好，放回桌角。
      过了很久，才说：“明天吧。”
```

**希望带来的感觉：** 行本身带着节奏，读者不必总在视觉折行处重新拼接意思。把排版当作一种轻微的朗读提示。

**值得大胆试的细节：** 给每行设置一个长度范围，在范围里优先选择合适的标点断开；保留原文和原段落关系，只调整显示换行。不要逢逗号就另起一行，也不要擅自给作者划重点。

**边界与验证：** 排版会介入作者语气，小说可能被排得过分像诗，论述文本也可能碎掉。把它作为可选的文学阅读样式，用叙事、对话、论述三种文本对照试读；重点判断节奏是否自然、意思是否被割裂，而非只看截图好不好看。

### 方向三：让中文变成一页“竖排书”

**想象的画面：** 中文从上往下读，列从右向左排列。列与列之间留出空隙，标题落在右侧；宽窗口可以呈现并列的两页，中间留一道书脊般的空白。

它探索的是另一种阅读方向：横向铺开的终端，也可以容纳一块安静的竖排中文书页。尤其可以拿散文、诗歌、古典文本做实验。

**希望带来的感觉：** 同样的字，换一种排列方向，就可能从“屏幕上的信息”变成“正在读的一本书”。这是一种形式和氛围的选择，不预设它更高效。

**值得大胆试的细节：** 先做没有边框、没有仿旧纹理的极简竖排，只用字与空白建立书页感；双页也不必画出书的轮廓。

**边界与验证：** 标点、引号、英文、数字都需要专门考虑，不能简单地每个字后插入换行。当前以横排为基础，这个方向的改动范围最大。先拿一小段纯中文和一段中英混排做静态版式样稿，判断是否愿意持续读，以及混排是否破坏节奏，再考虑实现。

### 本轮判断

三种方向分别探索 **空间的疏密、语言的节奏、文字的方向**。第一种最适合成为日常默认样式，第二种最值得检验“排版能否帮助理解语气”，第三种最适合作为天马行空的形式实验。

如果接下来只做一个视觉样稿，建议先拿同一段中文做“纸页”和“语流”对照。先确定想要的阅读气质，再决定排版规则；本轮不增加实现任务。

### 补充约束：与低暴露模式的关系

用户指出低暴露模式的兼容问题。上一轮关于“纸页适合作为日常默认样式”的判断只适用于普通阅读模式；若低暴露是主要使用场景，则需重新排序。

当前低暴露模式采用诊断信息、左对齐的正文区域和日志前缀，正文区域随窗口调整，最多占八行。渲染与分页都有单独分支，见 [reader_view.rs](../../src/reader_view.rs) 的 `draw_discreet` 和 [reader_state.rs](../../src/reader_state.rs) 的 `paginate_for_config`、`discreet_chunks`。

冲突主要在视觉目标：居中纸页、大幅留白、诗式断行和竖排都会增加“这是阅读界面”的辨识度。隐藏书名并不能消除这种整体形态。

| 方向 | 低暴露模式中的判断 | 可保留的部分 |
| --- | --- | --- |
| 纸页 | 大留白、章名陈列、双页感与日志外观冲突 | 在现有左对齐区域内控制行长、保持正文起始列稳定 |
| 语流 | 大量短句独占行容易呈现诗歌形态 | 在接近行尾时优先选择自然断点，保持整体密度，避免频繁空行 |
| 竖排 | 形式差异明显，不适合低暴露模式 | 作为普通阅读模式的独立实验保留 |

低暴露模式更适合尝试细微的排版改善：正文各行起点一致；前缀与正文有清楚而克制的视觉层级，避免装饰抢走注意；折行尽量减少不自然的断句。层级调整不能靠一味降低正文对比度，具体颜色仍需结合终端主题试读。

建议普通模式与低暴露模式分别定义排版样式，共用原文位置；切换后重新排版并保持阅读位置。不要让普通模式的竖排、大留白等选择直接进入低暴露模式。这是方案约束，尚未实现或验证。

验证需同时看两件事：近距离连续读是否舒服，以及缩小或远看时整体是否显得像专门的阅读界面。日志外观也无法保证旁人识别不出正文内容。

## 施工记录：低暴露模式的细微排版

2026-10-13，用户授权实施。落实本轮收敛的低暴露排版方向：

- 沿用已有的固定宽度日志前缀与左对齐正文列；取消渲染阶段的二次折行，保留分页给出的缩进和行边界。没有前缀的行也保留前缀栏空间。
- 日志级别词保留终端语义颜色，同时使用弱化样式；正文继续继承终端前景色。弱化效果取决于终端对 DIM 样式的支持。
- 仅在正文宽度至少 24 列、当前行已到最后八分之一范围内时，优先沿合法断行位置上的停顿标点换行。短窗口继续使用原有折行方式，不额外增加空行。所有行沿用原文字符锚点。

普通阅读模式的大留白、语流和竖排仍保留为讨论方案。本次没有实现它们。阅读舒适度与整体暴露程度仍需真实终端试读。

施工验证：Rust 格式检查与 Clippy 均通过；完整测试 227 项通过，1 项需要私人网络书库的测试按既有设置跳过。新增验证覆盖临近标点断行、原文字符映射、窄窗口、跨页锚点、缩进与空行，以及前缀弱化不影响正文样式。Release 构建完成，已更新 `Reader-cli/reader.exe`，与构建产物的 SHA-256 一致；旧程序备份于 `build/reader-before-typography.exe`。

## 施工记录：翻页上下文衔接与普通模式语流排版

2026-10-13，用户授权实施“翻页上下文”与“探索阅读模式（语流断行）”：

- **翻页上下文衔接（Page Overlap Context）**：
  - 核心分页改造：同章节从第 2 页起，顶部保留上一屏最后一行作为阅读上下文（`overlap_lines = 1`），新内容从下一行开始排列。
  - 严格保持字符锚点与进度单调性：当前页的 `source_start` 锚定在本页**首行新内容**的字符起始处。翻页保存的阅读进度 `TextPosition` 单调递增，不因重叠行而后退，重新加载与书签恢复均精确命中。
  - 跨章节与小窗口保护：跨章节首页不重叠上一章节末行；窗口可用高度不足 4 行时自动降级为不重叠。
  - 视觉弱化区分：渲染阶段对重叠上下文行采用 `palette.muted()` 弱化样式展示，与下方正常正文区分；若重叠行内包含搜索匹配词，搜索高亮依然正常生效。
  - 快捷操作与持久化：增加快捷键 `o`（Overlap）支持即时切换翻页上下文衔接；配置项 `page_overlap` 自动持久化至 `configuration.json`。
- **普通阅读模式语流断行（Natural Flow Breaks）**：
  - 将临近标点断行机制引入普通阅读模式：行宽 $\ge 24$ 且处于行末最后 $1/8$ 范围内时，优先在合法的停顿标点（逗号、句号、分号等）处换行，避免中文词语被硬生生横向切断，赋予正文自然的语流节奏。
  - 支持配置项 `natural_breaks`（默认开启）。
- **施工验证**：
  - 代码格式检查 `cargo fmt --check` 通过；
  - 静态检查 `cargo clippy --all-targets -- -D warnings` 零警告通过；
  - 完整测试套件通过（230 项测试全部通过，1 项私有书库跳过测试按既有设置跳过）；
  - 新增测试覆盖翻页上下文切分、跨章节隔离、极矮窗口降级、原文字符单调递增性、快捷键 `o` 映射与配置持久化、以及重叠行弱化渲染样式。


## 第三轮：从错误日志切换到 Agent Terminal（2026-10-15）

本轮目标同时兼顾低暴露和长时间阅读舒适性，明确淘汰“固定错误栈 + 底部逐行日志前缀”的**可见布局**，不再将 EPUB 正文渲染为 INFO/WARN/ERROR 行。

- 采用模拟 Coding Agent 会话：固定的 Agent session、Inspect 提示、Read 调用、工具输出正文和底部范围提示。所有会话文案与文件路径均为本地 UI 占位符，不存在真实模型调用或执行。
- 正文作为完整的多行 Read 工具输出，取消行级日志前缀，保留源文件缩进与空行；顶部最多 4 行、底部最多 2 行，其余用于阅读。
- 低暴露阅读宽度默认 64 终端列，最多 72 列，并为左缩进及右边距留空间；窄终端自动降级。默认仍使用分页而非逐行滚动。
- F12 立即切换到不含正文、书名、查询或通知的折叠 Agent 会话。低暴露界面不显示应用通知；正常阅读 UI 不改变。
- 兼容原有 `discreet_mode` 配置键；删除不再需要的日志级别、动态时间戳和逐行前缀状态。旧 `discreet_stack()` 公共接口暂时保留兼容，不再参与渲染。
- 已为 Agent 布局、重绘一致性、文本缩进和折叠私密性调整测试，但尚未在本轮实际执行 Rust 编译与测试。不能据此声称兼容性已获验证。

**实际取舍：** Agent 终端布局比错误日志更自然，也有更大的正文区域；但屏幕中会出现更多中文，近距离隐蔽性降低。没有真正运行 AI，也不能避免其他人直接读到屏幕内容。下一步必须在真实终端试读和截图验收，再判断是否加入渐进滚动。
