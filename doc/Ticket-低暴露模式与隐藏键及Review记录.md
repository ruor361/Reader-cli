# Ticket：低暴露模式（Discreet Mode）、全局隐藏键与 Review 问题记录

## Ticket 信息

- 类型：优化（交互设计）
- 状态：已实现，自动化验收通过
- 目标：明确低暴露模式中的可用能力，并增加一个在任何阅读状态下都可立即进入的伪装屏；优先保证阅读体验、行为可预测和阅读元数据降暴露。
- 说明：本文先作为设计基线，现已按下方边界完成实现；程序真实错误仍不属于伪装范围。
- 边界：低暴露模式降低旁观者直接识别阅读行为的概率，不提供数据加密、访问控制、防截屏或操作系统级隐私保护。

## 修复前的背景与问题

修复前的低暴露模式只有渲染层分支：[reader_view.rs:17](../src/reader_view.rs#L17) 检测到
旧配置字段 `privacy_mode` 后直接绘制伪堆栈并返回，但 [reader_input.rs:221](../src/reader_input.rs#L221)
仍按普通阅读模式分发全部按键。其结果不是“部分功能不可用”，而是很多功能已经执行、界面却不给反馈：

- `g`、`t`、`/`、`M`、`?` 会打开不可见的弹层，后续按键又被弹层接管。
- `b`、`s`、`c` 会修改书签或配置，但成功提示不可见。
- `p` 在没有弹层时可以正常退出低暴露模式；一旦误入不可见弹层，它可能变成输入字符或被忽略。
- `q` 在不可见弹层中可能失效，只有输入层最先处理的 `Ctrl+C` 始终可以退出。
- 修复前的低暴露布局仅为正文保留 1 行（[reader_state.rs:11](../src/reader_state.rs#L11)），不适合持续阅读。
- 修复前的固定堆栈含有会自曝阅读器与伪装用途的函数名，会直接破坏低暴露目标。
- [reader_view.rs:468](../src/reader_view.rs#L468) 会重复同一段堆栈直到填满屏幕，视觉上不像真实错误。

因此需要先定义模式和输入权限，再设计画面。不能继续依赖“普通输入逻辑 + 低暴露渲染提前返回”的组合。

## 模式定义

本设计把“低暴露阅读”和“紧急隐藏”明确拆成两个用途不同的模式：

| 模式 | 用途 | 是否可阅读 | 是否持久化 | 进入/退出 |
| --- | --- | --- | --- | --- |
| 普通阅读 | 完整阅读体验 | 是 | 正常保存阅读状态与配置 | 默认状态 |
| 低暴露阅读 | 隐去书名、章节、进度和查询等元数据，同时维持基本阅读 | 是，使用较小正文区 | `discreet_mode` 持久化；兼容读取旧 `privacy_mode` | 阅读主界面按 `p` 切换 |
| 隐藏屏 | 有人靠近时立即把整个终端变成可信的 JS 报错现场 | 否 | 绝不持久化 | 任意状态按 `F12` 进入，再按 `F12` 原样返回 |

隐藏屏不是低暴露模式的另一种主题，也不改变 `discreet_mode`。从普通阅读进入隐藏屏就回到普通阅读；从低暴露阅读进入就回到低暴露阅读。进入前如果存在搜索输入或其他弹层，也在内存中原样保留，恢复时不能丢字符、改变位置或触发确认。

程序真实发生的解析、存储或终端错误仍必须报告真实错误，不能被伪堆栈替换。伪堆栈只是一种由用户主动进入的运行时画面。

## 隐藏键选择

第一版采用 `F12`，不增加字符键别名：

- 与正文搜索、章节过滤等文本输入无冲突，可以在任何弹层中优先拦截。
- 与现有 `F1` 帮助、`p` 低暴露模式和阅读导航不冲突。
- 用户容易把它和开发者工具/诊断画面建立联系，伪装画面也更自然。
- 单键可以快速进入，再按同一键恢复，心智模型简单。

如果后续真机测试发现部分笔记本必须组合 `Fn` 才能触发 `F12`，再讨论是否增加可配置键位；第一版不要直接占用 `h`、`x`、反引号等可输入字符，也不要用 `Esc`，避免破坏搜索、过滤和弹层关闭行为。

输入优先级建议固定为：

1. `Ctrl+C`：任何模式都允许保存并退出。
2. `F12`：任何普通/低暴露/弹层状态进入隐藏屏；隐藏屏中恢复原状态。
3. 隐藏屏：除终端 resize 外，忽略其他全部输入，不产生任何 effect。
4. 低暴露模式：先处理 `p`，再按下方白名单分发。
5. 普通模式：沿用现有弹层和阅读输入规则。普通文本输入中的 `p` 仍是普通字符，不应被低暴露切换抢占。

## 低暴露模式按键白名单

低暴露模式应使用显式白名单，而不是从普通模式逐项打补丁。第一版建议如下：

| 按键 | 低暴露模式 | 设计理由与反馈 |
| --- | --- | --- |
| `p` | 可用 | 退出低暴露模式；必须始终可用，不受其他输入状态影响。 |
| `F12` | 可用 | 进入全屏隐藏；再次按下恢复低暴露阅读。 |
| `Ctrl+C`、`q` | 可用 | 保存并退出。低暴露模式不会创建弹层，因此 `q` 行为稳定。 |
| `j`、`Down`、`Space`、`PgDn` | 可用 | 下一低暴露阅读页，并按现有逻辑保存稳定位置。 |
| `k`、`Up`、`PgUp` | 可用 | 上一低暴露阅读页，并按现有逻辑保存稳定位置。 |
| `Home`、`End`、`G` | 可用 | 直接到开头/结尾；属于无弹层、可逆的阅读导航。 |
| `b` | 可用 | 在当前位置加书签；只显示不含章节、书名和进度的通用提示 `Bookmark saved`。 |
| `g`、`t`、`/` | 禁用 | 百分比、章节和搜索都依赖可见弹层，并可能暴露输入内容。第一版不做伪装输入框。 |
| `M`、`?`、`F1` | 禁用 | 元数据和完整帮助会破坏低暴露画面；帮助内容也会暴露阅读器身份。 |
| `n`、`N` | 禁用 | 依赖搜索上下文，低暴露模式又不提供搜索反馈，容易产生不可解释的跳转。 |
| `s` | 禁用 | 低暴露模式本来就不显示进度，切换该配置没有即时价值。 |
| 其他键 | 忽略 | 不改变位置、弹层、配置或持久化数据。 |

禁用键不能创建隐藏弹层，也不能静默修改状态。可以在低暴露正文区的提示行短暂显示
`Unavailable in discreet mode`；提示本身不得包含按键对应的真实查询、书名或章节信息。

## 低暴露阅读画面

低暴露模式仍然是阅读模式，所以正文不能继续固定为 1 行。建议使用自适应的三段布局：

1. 上部为一次性的 JS 诊断输出，截断到可用高度，不循环重复。
2. 下部为 4–8 行正文，终端高度充足时约占总高度的三分之一；只要终端至少有 4 行，正文就不能低于 4 行。更矮的极端终端把全部可用行交给正文，不再保留伪堆栈和状态栏。
3. 最底部 1 行只显示当前重排宽度下的物理行范围，例如 `rows 128-133/980`，不显示任何快捷键提示。

中文长文按全角字符约占 2 个终端列计算：48–64 列（约 24–32 字），默认取 64 列（约 32 字）并靠左显示，只保留 1 列左内边距，不在终端中居中。显式 `text_width` 在低暴露模式中收敛到 48–64 列。终端低于 52 列时优先保留 `I/W/E ` 最小前缀，正文使用剩余宽度并允许暂时低于 24 个汉字；极端宽度只要求安全裁切且不崩溃。分页和渲染必须调用同一个宽度解析函数，避免视觉二次换行导致位置或翻页不一致。

正文采用稳定的日志化装饰，进一步降低一眼识别为阅读内容的概率：

- 每个非空物理正文行都带日志前缀；段落分隔空行继续保持空白。
- 翻页或进入低暴露模式时取得本地时间，同一页重绘期间保持固定；本地时区不可用时回退 UTC。
- 级别使用 `INFO/WARN/ERROR = 80%/15%/5%`，每个非空物理行独立且稳定生成。
- 默认完整前缀 `13:21:06 INFO  ` 占 15 列。终端无法同时容纳前缀和正文时依次降级为 `21:06 I `、`I `；低于 52 列仍优先保留最小前缀。
- 前缀和正文按独立 span 渲染，时间戳和间隔使用弱化灰，正文使用低暴露专用正文色；只给 `INFO/I`、`WARN/W`、`ERROR/E` 关键字着色。分页宽度提前扣除前缀，禁止渲染阶段再次折行。

低暴露模式和普通阅读都继承终端默认前景与背景，不再维护 dark/light 主题。日志时间、状态栏和去上下文通知使用终端 ANSI 弱化色，级别使用终端 ANSI 的绿色、黄色和红色。因此实际颜色由用户的终端 profile 决定。字号也由终端控制而非 TUI 控制；Windows Terminal 推荐 Cascadia Mono 14pt、normal weight，高 DPI 或长时间阅读可选 16pt。

正文使用正常前景色，不再叠加 `DIM`，以保证连续阅读的清晰度；不显示书名、作者、章节名、百分比、搜索词、书签标签或真实文件路径。切换普通/低暴露模式和终端 resize 时，继续使用稳定 `TextPosition` 锚定当前位置，不能因为重新分页而跳段。

通知必须是去上下文的固定文案，例如 `Bookmark saved`、`Start reached`、`End reached`。不能把现有含书签 ID、章节序号或百分比的通知直接搬进低暴露画面。

## 全屏隐藏画面

### 画面原则

- 整个终端只绘制伪错误，不保留正文行、HUD、弹层、通知、标题或进度。
- 隐藏渲染函数不应接收 `BookDocument`、当前页、查询或书架记录，只接收终端尺寸和通用语义色；从接口上阻止误泄露。
- 模拟“在当前目录运行 JS 后报错”，命令使用相对路径，但不调用 `current_dir()`、不显示真实用户名或真实绝对路径。
- Windows 和 Unix 可以分别使用 PowerShell/普通 shell 的固定合成工作目录；路径内容必须是中性的开发项目，例如 `dashboard-client`。
- 一次堆栈后回到命令提示符，剩余区域留空；不要循环堆栈，不做随机行号或闪烁，以免恢复前后画面突变。
- 进入/退出隐藏屏不保存配置、不保存进度、不加书签、不关闭弹层。resize 只重绘伪错误。

### 颜色语义

颜色按语义拆成 span，不整行染红：

- `TypeError: ...`：亮红并加粗。
- 源码下方的 `^`：亮红；出错源码本身保持普通前景色。
- `at`、括号和 `:line:column`：弱化灰色；函数名和路径使用普通前景色。
- shell 提示符和执行命令：普通前景色，不能伪装成错误。
- 背景继承终端默认背景；禁止红色背景和整屏高亮。

这样能做到“错误应该红，调用链保持正常”，并让实际颜色跟随终端 profile。

## 状态与实现边界（供后续实现讨论）

- `discreet_mode` 属于 `ReaderConfig`，表示持久化阅读偏好；读取时兼容旧 `privacy_mode`，两个字段同时存在时以新字段为准，保存时只写新字段。
- `hidden` 只属于当前 TUI 会话的运行时状态，不能写入 `configuration.json`、`library.json` 或 sidecar。
- 输入层应先完成全局键路由，再进入 overlay/reading 路由；低暴露白名单必须集中声明。低暴露底栏不得从白名单生成快捷键提示。
- 隐藏画面应使用中性的 `discreet_stack()`，内容本身不能出现阅读器语义。
- 从隐藏屏恢复时，应恢复进入前的普通/低暴露状态、当前位置、overlay、未提交输入、搜索结果和通知剩余状态。
- 若决定隐藏期间通知计时暂停，需要显式记录进入时刻；建议第一版继续按真实时间过期，避免为伪装屏维护额外计时语义。

## 验收场景

1. 普通阅读、低暴露阅读、搜索输入、章节过滤、帮助和元数据弹层中按 `F12`，画面都立即完全变成同一份伪 JS 错误。
2. 隐藏画面中连续按普通导航、字符、`p`、`q`、`Esc`、`Enter`，阅读位置和所有持久化数据均不变化；只有 `F12` 恢复、`Ctrl+C` 保存退出。
3. 从隐藏画面恢复后，位置、模式、弹层和未提交输入与进入前逐项一致。
4. 隐藏期间 resize 或通知过期不会短暂闪出正文、书名、查询、真实路径或 HUD。
5. 低暴露模式只接受白名单；禁用键不会创建 overlay，也不会产生 `SaveConfig`、`SaveProgress` 或书签 effect。
6. 低暴露模式下 `p`、导航、书签、退出都有可见且去上下文的反馈，正文在常见 24 行终端中至少有 4 行；底栏只显示 `rows {start}-{end}/{total}`。
7. 终端宽度充足且未配置 `text_width` 时，低暴露正文宽度为 64 列，一行无空格中文长文正好容纳约 32 个汉字；配置值低于 48 或高于 64 时分别收敛到 48/64 列。
8. 低暴露正文从终端左侧第 2 列开始，不能因 `text_width` 变化重新居中；正文和背景均使用 `Color::Reset` 继承终端默认色。
9. 使用终端配色时，错误标题和 caret 使用 ANSI 红色；堆栈调用链保持正常/弱化前景色，不出现整屏红色。
10. 伪堆栈快照中不包含真实书名、作者、章节、搜索词、书签、文件路径、用户名，以及 `Discreet`、`Reader`、`Book` 等自曝用途的标识符。
11. 程序真实错误仍走真实错误处理路径，不受 `discreet_mode` 或隐藏屏影响。
12. 同一页连续重绘时日志时间、级别和前缀位置完全一致；所有非空物理行都有前缀、空白行没有前缀，级别边界严格为 80/15/5，完整、紧凑、最小和极端无前缀四档都不产生二次折行。
13. 底栏行号为 1-based，包含段落空白行；翻页连续，resize 后按新宽度重新计算总行数且不改变稳定 `TextPosition`。

## Review 问题记录

以下问题与低暴露交互优化分开实现，但一并记录在本 Ticket，当前均已修复并有回归测试。

### REV-P1-01：`shelf refresh` 篡改最近阅读书籍（已修复）

- 位置：[bookshelf.rs:123](../src/bookshelf.rs#L123)、[storage.rs:178](../src/storage.rs#L178)
- 现象：刷新对每个扫描文件调用 `add_book()`，而 `add_book()` 会更新 `last_book_id`。刷新后星标和 `resume` 指向扫描顺序中的最后一本，而不是最近实际阅读的一本。
- 验收：刷新前后的 `last_book_id` 必须完全一致；新增、更新、恢复和失败扫描都不能改变最近阅读。只有明确打开阅读器的 `record_open(book_id)` 可以更新最近阅读语义。

### REV-P1-02：仓库硬编码 Windows GNU，Linux/macOS 无法本机构建（已修复）

- 位置：[.cargo/config.toml:1](../.cargo/config.toml#L1)、[rust-toolchain.toml:2](../rust-toolchain.toml#L2)
- 现象：仓库全局指定 Windows target 和 Windows host，其他平台会尝试运行 Windows 编译器或依赖缺失的交叉链接器。
- 验收：先明确项目是否 Windows-only。若不是，应移除仓库级 Windows host/target 强制设置，把 Windows GNU 配置改为开发机文档或显式的目标命令，并至少验证 Windows、Linux、macOS 的本机 `cargo build/test` 配置不会被仓库强制交叉编译。

### REV-P1-03：核心 JSON 存储不是原子写入，可能清空整个书架（已修复）

- 位置：[storage.rs:138](../src/storage.rs#L138)，同类位置还包括配置和 sidecar 写入。
- 现象：直接截断再重写 `library.json`。断电、磁盘满或进程中断可能留下半个 JSON；下次启动会把损坏文件移走并初始化空书架。
- 验收：`library.json`、`configuration.json` 和所有 sidecar 统一使用同目录临时文件，完整写入并 flush 后做跨平台原子替换；替换失败保留旧文件并返回错误；临时文件可清理；增加写入失败/损坏恢复测试。Windows 目标存在时，不能假设 `std::fs::rename` 可直接覆盖已有目标。

### REV-P2-01：Sidecar 可能写到托管书架之外（已修复）

- 位置：[main.rs:258](../src/main.rs#L258)、[main.rs:228](../src/main.rs#L228)
- 现象：同步 sidecar 只检查是否配置 `bookshelf_dir`，不检查书籍是否位于该目录。已有的外部书籍会提前返回，绕过复制进托管书架的流程，并在原文件旁生成 sidecar。
- 验收：只有 canonicalized 书籍路径确认位于 canonicalized `bookshelf_dir` 下才允许写 sidecar；配置书架后再次导入旧外部记录时，应进入复制/去重流程；任何目录外 sidecar 写入都返回明确错误且不创建文件。

### REV-P2-02：中文书名破坏书架列对齐（已修复）

- 位置：[shelf.rs:729](../src/shelf.rs#L729)
- 现象：按 Unicode 字符数截断，并依赖普通格式宽度填充。中文通常占两列，导致标题、作者、进度等列错位或被裁切。
- 验收：截断、补空格和列宽计算全部基于 `unicode-width` 的终端显示宽度；覆盖中文、英文、混排、组合字符、emoji 和超窄终端测试；每行各列起始显示列一致。

### REV-P2-03：配置的书架目录消失时仍报告刷新成功（已修复）

- 位置：[bookshelf.rs:90](../src/bookshelf.rs#L90)
- 现象：目录不存在时返回空报告，CLI 随后打印零计数的成功结果，路径拼错、磁盘未挂载或目录被删除都会被隐藏。
- 验收：已配置或显式传入的目录不存在、不是目录或不可读时，`refresh` 返回包含具体路径和原因的错误；CLI 以非零状态退出，不打印成功摘要，也不能把全部书籍误标为 missing。
